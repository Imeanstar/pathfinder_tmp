# 보안 감사 (Security Audit and Refinement)

**감사일**: 2026-08-24
**범위**: `app/` 전체(백엔드 API·프론트엔드 정적 자산), 배포 파이프라인(GitHub Actions), 시크릿 관리
**방법**: 코드 정독 + 실제 요청으로 재현(TestClient) → 발견 항목마다 실패하는 테스트를 먼저 작성해 재현한 뒤(TDD) 수정 → 재검증. 아래 표의 "재현 테스트" 열이 그 증거다.

이 문서는 매번 처음부터 다시 감사하기보다, 다음 감사 때 "지난번엔 뭘 봤고 뭐가 남았는지"를 이어받기 위한 것이다. 새로 발견한 항목은 표에 이어서 추가하고, 고친 항목은 상태만 바꾼다.

---

## 1. 위협 모델

이 서비스가 다루는 자산과 그에 대한 위협을 4가지 축으로 나눈다(아주대 AI 부트캠프 Part 2 "LLM 4대 위험" 프레임 — 악성 URL·프롬프트 인젝션·PII 노출·불쾌감 콘텐츠 — 을 이 서비스의 실제 데이터 흐름에 맞게 확장).

| 축 | 이 서비스에서의 구체적 위협 |
|---|---|
| **PII 노출** | 학생 성적표(이름·학번)가 서버에 남거나 LLM에 그대로 전달됨 |
| **프롬프트 인젝션** | 자유 텍스트 입력(성적표 텍스트, 프로젝트 제목, 챗봇 질문)이 시스템 프롬프트를 무력화해 거짓 졸업 판정·유해 답변을 유도 |
| **XSS(콘텐츠 삽입)** | LLM 생성 텍스트나 외부 스크래핑 데이터(아주허브)가 이스케이프 없이 innerHTML에 들어가 스크립트 실행으로 이어짐 |
| **가용성/DoS** | 무제한 업로드 크기, 처리 안 된 예외로 인한 서버 오류·정보 노출 |
| **시크릿 관리** | API 키·해시 페퍼가 코드/이미지에 박히거나 클라이언트에 노출됨 |

## 2. 감사 결과

### 2.1 이미 잘 되어 있던 것 (기존 설계 확인)

| 항목 | 근거 |
|---|---|
| PII는 서버에 저장·로깅되지 않음 | `app/masking.py`(라벨 기반 마스킹 + `scan_for_leftover_pii` 2차 검사, 실패 시 fail-closed), `app/api.py` 상단 docstring — 원본 PDF 바이트·마스킹 전 텍스트를 로그/응답에 남기지 않음 |
| 로그인 이메일 원문 미저장 | `app/auth.py`가 이메일이 아니라 `HMAC-SHA256(pepper, email)`만 저장(`app/user_store.py`) — pepper는 `EMAIL_HASH_PEPPER` GCP Secret Manager 시크릿으로 배포(`.github/workflows/deploy.yml`), 코드의 개발용 기본값은 배포에 안 쓰임 |
| 프롬프트 인젝션 2단계 방어 | `app/guardrail.py` — 키워드 패턴(1차, 항상 실행) + Gemini 분류기(2차, 옵션) + `GUARDRAIL_ENABLED` 토글 |
| API 키·시크릿이 코드/이미지에 없음 | `GOOGLE_API_KEY`·`EMAIL_HASH_PEPPER`는 `--set-secrets`로 Secret Manager에서 런타임 주입(`docs/배포.md`), `.env`는 `.gitignore` 처리, `Dockerfile`이 `.env`를 COPY하지 않음 |
| SQL 인젝션 없음 | `app/user_store.py`의 SQLite 쿼리 전부 파라미터 바인딩(`?`) 사용, 문자열 포매팅으로 쿼리를 조립하는 곳 없음 |
| `/api/config`가 시크릿을 노출하지 않음 | `google_client_id`만 반환 — OAuth 클라이언트 ID는 공개돼도 되는 값(클라이언트 시크릿이 아님, 브라우저 Google Identity Services가 원래 쓰는 값) |
| CORS 미설정이 오히려 안전한 기본값 | 프론트·백엔드가 동일 출처(같은 FastAPI 앱이 정적 파일도 서빙)라 `CORSMiddleware` 자체가 불필요 — 다른 출처의 JS가 이 API를 호출할 수 없음(브라우저 기본 정책) |
| 마스킹된 텍스트만 LLM에 전달 | `app/parser.py` — PDF 원문 이미지·전체 텍스트가 아니라 `mask_and_validate()`를 통과한 텍스트만 `structure_fn`(Gemini)에 전달 |

### 2.2 발견해서 고친 것 (Refinement)

| # | 발견 | 위험도 | 조치 | 재현 테스트 |
|---|---|---|---|---|
| 1 | `app/guardrail.py` 설계상 "2경로"(성적표 텍스트 + 프로젝트 제목) 방어를 명시했는데, 실제로는 프로젝트 제목(`/api/plan`의 `projects[].title`) 경로엔 인젝션 검사가 없었다 — 자유 입력인데 검증 없이 그대로 통과됨 | 중 | `/api/plan`에 `_reject_injected_project_titles()` 추가 — 성적표 텍스트와 동일한 `detect_injection` + `GUARDRAIL_ENABLED` 토글 적용 | `tests/test_api.py::test_plan_rejects_project_title_with_injection` |
| 2 | 대시보드 로드맵 카드(`courseRowHtml`/`activityCardHtml`, 2026-08-24 신설)가 `item.reason`(Gemini가 다시 쓸 수 있는 문구, `soften_recommendation_reasons`)과 `item.name`/`item.org`(아주허브 스크래핑 데이터)를 이스케이프 없이 `innerHTML`에 꽂았다. `upload.js`는 이미 `escapeHtml()`을 쓰는 관례가 있었는데 이 두 함수만 빠져 있었다 | 중 | 두 함수 전체에 `escapeHtml()` 적용. `item.url`도 속성 주입 방지로 이스케이프하고, `http(s)`가 아닌 스킴(`javascript:` 등)은 아예 링크를 만들지 않도록 화이트리스트 검사 추가 | 수동 검토로 발견(자동화된 XSS 테스트는 아직 없음 — 3.2 참고) |
| 3 | `/api/upload`에 파일 크기 제한이 없어 `file.read()`가 요청 바디 전체를 무제한으로 메모리에 올렸다(DoS 여지) | 중 | `MAX_UPLOAD_BYTES = 10MB` 초과 시 파싱 전에 413으로 즉시 거부 | `tests/test_api.py::test_upload_rejects_oversized_file` |
| 4 | PDF가 아니거나 손상된 파일을 업로드하면 `pdfplumber`의 예외(`PdfminerException` 등)가 잡히지 않고 FastAPI 기본 500으로 그대로 새 나갔다 — 프로덕션에서 스택트레이스가 응답에 노출될 위험 | 중 | `except Exception`으로 감싸 정직한 422("PDF 파일을 열 수 없습니다")로 변환 | `tests/test_api.py::test_upload_rejects_corrupt_pdf_with_clean_error_instead_of_500` |

### 2.3 확인했지만 지금 범위에서 고치지 않기로 한 것 (알려진 한계)

의도적으로 남겨두는 항목 — 왜 지금 안 고치는지 이유를 남긴다(나중에 실서비스로 확장할 때 재검토).

| 항목 | 이유 |
|---|---|
| Rate limiting 없음(요청 횟수 제한) | Cloud Run `--allow-unauthenticated`로 누구나 호출 가능하지만, 교내 데모 규모(수십~수백 명)에선 비용·가용성 리스크가 낮다. 실서비스 확장 시 Cloud Armor나 API Gateway 레벨에서 처리하는 게 맞다(애플리케이션 코드에 넣을 문제가 아님) |
| 아주허브 스크래핑 데이터 자체의 무결성 검증 없음(HTML 인젝션이 원본 사이트에 있었다면?) | 확률이 낮고, `escapeHtml()` 적용(2.2-#2)으로 렌더링 단계에서 이미 방어됨 — 원본 검증까지는 과함 |
| Gemini 응답에 대한 콘텐츠 안전 필터(욕설·유해 콘텐츠) 없음 | Gemini API 자체에 기본 안전 설정이 있고, 시스템 프롬프트가 "졸업·진로 상담"으로 범위를 좁혀둠 — 별도 Model Armor류 레이어는 이 프로젝트 규모에서 과함 |
| 로그인 세션에 만료 시간 없음(`localStorage`에 무기한 저장) | 서버 세션이 아니라 프론트 전용 "로그인했다" 표시일 뿐이고(`app/static/js/auth.js` 주석 참고), 서버는 매 요청마다 구글 ID 토큰이 아니라 이미 검증된 `email_hash`만 받는다 — 탈취돼도 할 수 있는 일이 "내 최근 로드맵 조회"뿐이라 실피해가 작음. 실서비스라면 httpOnly 세션 쿠키로 바꿔야 한다(`app/static/js/auth.js` 상단에 이미 명시돼 있음) |
